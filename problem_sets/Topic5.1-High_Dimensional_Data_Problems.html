Setup#

In this problem set we will work with the Tennessee Eastman Process (TEP), a simulated chemical plant that Eastman Chemical published in 1993 as a benchmark for process control and monitoring. The plant has a reactor, a condenser, a vapor–liquid separator, a recycle compressor and a stripper, and it converts reactants A, C, D and E into products G and H (plus a byproduct F). The control system records 52 variables every 3 minutes:

columns

what they are

XMEAS_01 – XMEAS_22

continuous measurements: flows, pressures, levels, temperatures

XMEAS_23 – XMEAS_36

on-line gas analyzers (reactor feed, purge), mol%, updated every 6 min

XMEAS_37 – XMEAS_41

product analyzer, mol%, updated every 15 min

XMV_01 – XMV_11

valve positions set by the control system, % open

A few variables come up by name below: XMEAS_01 A feed (kscmh), XMEAS_02 D feed (kg/h), XMEAS_04 A and C feed (kscmh), XMEAS_07 reactor pressure (kPa), XMEAS_09 reactor temperature (°C), XMV_03 A feed valve, XMV_10 reactor cooling water valve and XMV_11 condenser cooling water valve. The full list is in the benchmark’s documentation.

The file data/tep_sensors.csv contains four runs of the plant:

The fault is active from the first sample of each fault run. The fault column holds the fault number (0 for normal), and sample and time_h count samples and hours within each run.

A3. What “nearby” means in 52 dimensions (10 pts)#

The chapter’s mean_nn_distance measures how far each point is from its nearest neighbor. On its own this number doesn’t have a natural scale, so we will compare it to the mean pairwise distance (the average distance over all pairs of distinct points):

\[ \rho = \frac{\text{mean nearest-neighbor distance}}{\text{mean pairwise distance}} \]

If \(\rho\) is near 0 then every point has close neighbors compared to the size of the cloud, and as \(\rho\) approaches 1 the nearest point is not much closer than a typical one.

Part C — Open Ended (35 pts)#

Part B showed that the information in the 52 sensors is spread very unevenly. Some sensors repeat each other almost exactly, faults 1 and 4 each show up clearly in a single sensor, and fault 5 barely shows up anywhere. A3 also showed that with all 52 axes, normal samples are not very close to each other either. This raises a practical question: if we build an alarm for an operator, how many sensors should it watch? An operator dashboard only has room for a handful of sensors, but is that a compromise, or is it actually better than watching everything?

We will answer this using the simplest possible alarm rule, which only needs the summary statistics from the chapter. The range alarm learns each sensor’s minimum and maximum from the first 250 samples of the normal run, and a sample raises an alarm if any sensor on the panel falls outside its learned range. We can score a panel in two ways:

  • the false-alarm rate, the fraction of the last 250 normal samples that raise an alarm;

  • the detection rate for each fault, the fraction of that fault run’s samples that raise an alarm.

Exercise 5

1. Score the full panel. Implement the range alarm and report the false-alarm rate and the three detection rates for a panel that watches all 52 sensors.

2. Build a short panel. Choose a panel of at most six sensors. Use the fault–sensor correlations from Part B to pick sensors that carry each fault, and the A1 pairs to avoid spending two slots on sensors that repeat each other. Report your panel and its four rates.

3. Choose a panel. In two sentences, say which panel you would give the operator and why, citing your rates, and use A3 to explain the difference in false-alarm rate between the two panels.
