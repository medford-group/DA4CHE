Setup#

data/membranes_fabrication.csv is a gas-separation membrane database: 1,672 records covering more than 280 membranes, hand-extracted from 42 papers published between 2009 and 2022 (github.com/tenoriolms/database_membranes, Apache-2.0). Each record says what the membrane was made of, how it was mounted, and the conditions it was tested at.

The task here is a database audit rather than a prediction anyone needs to make. Every record already states its material family. The question is whether a classifier can recover that family from the fabrication and testing metadata alone. If it can, the records are not independent samples of chemistry: they carry the fingerprint of how each sub-field runs and reports its experiments, and any model trained on the database inherits it. This is worth asking of a curated literature dataset before trusting anything built on it.

The file has been prepared for that question. No permeability or permeance column is in it. The columns that would give the answer away outright are also gone: subtype (47 values, not one shared between two families, so it is the label spelled differently), filler_loading (non-zero for every mixed-matrix membrane and for nothing else), and the material description.

source_ref, and why every split is by paper#

source_ref names the paper each row came from. It is not a feature — it is the grouping key, and every split below depends on it.

The 1,672 rows came from 42 papers, and one paper contributes 134 of them: its own handful of membranes, measured at many conditions. Split those rows at random and rows from the same paper land on both sides, so a classifier can score well by recognizing the paper rather than the chemistry. Every split below is therefore made by paper, with GroupShuffleSplit, and no paper appears in both the training and the test set. Part C measures what that costs.

Two more preparation decisions, both forced by the data:

  • Four families, not six. CMS (21 rows) and ceramic (24 rows) each come from a single paper, so a split by paper puts all of either class entirely on one side and the class becomes untrainable. They are dropped, leaving polymer, zeolite, MMM and MOF.

  • Missing values are imputed with the training-set median, inside the pipeline. The numeric columns are 16 to 99% complete — literature compilations record whatever each paper happened to report — and SVC cannot take a NaN. Doing it inside the pipeline is what keeps the test rows out of the median.

One helper builds the pipeline, with the categorical branch switchable. Parts A and B both turn on that switch.

def make_pipeline(use_categorical, C=10.0, gamma=0.1, categorical=None):
    """RBF-kernel SVC on the numeric columns, optionally plus one-hot categoricals.

    The numeric branch imputes with the training median and then standardizes; both are
    fitted inside the pipeline, so the test rows never contribute to either.
    """
    cats = CATEGORICAL if categorical is None else categorical
    branches = [('num', Pipeline([('impute', SimpleImputer(strategy='median')),
                                  ('scale', StandardScaler())]), NUMERIC)]
    if use_categorical and cats:
        branches.append(('cat', OneHotEncoder(handle_unknown='ignore', sparse_output=False), cats))
    return Pipeline([('prep', ColumnTransformer(branches)),
                     ('clf', SVC(kernel='rbf', C=C, gamma=gamma))])


def n_features(pipe):
    """How many columns the fitted preprocessor actually produces."""
    return pipe.named_steps['prep'].transform(X_train).shape[1]


print("make_pipeline ready")

handle_unknown='ignore' is not optional here. The test papers are papers the encoder has never seen, so they can easily report a support material or a sweep gas that appears nowhere in the training rows; without it, transform would raise.

Part B — Visualization (35 pts)#

In Part A, one-hot encoding gained more than every numeric column put together. That result is unspecific: five columns went in at once, so nothing yet says which of them carries the information, or which families it separates.

This part pins the effect down in two directions. Per-class metrics say which families the encoding rescued — overall accuracy hides that one family was already being classified well while another was barely being found at all. An ablation says which column does the work. Keep two groups of columns apart as you write: the material categoricals describe what the membrane is made of and how it is mounted (support_material, configuration), while the protocol categoricals describe how the permeation test was run and reported (sweep_gas, pore_size_type, provided_data_type). Which group wins is the thing to report.

Part C — Open Ended (35 pts)#

Everything so far has used C=10 and gamma=0.1, values handed to you with no justification, and a split by paper presented as simply the right thing to do. Part C tests both choices. The second one turns out to matter far more than the first.

The chapter’s opening section gives the correct procedure: split first, tune inside the training set, touch the test set once. That protocol has a hole in it when rows are not independent. You can follow every step and still leak, because the leak is in the split itself rather than in the tuning. With 1,672 rows drawn from 42 papers, this database is exactly that case. Measure the effect, then say what the database can honestly support.

Exercise 5

Summary#

  • Part A ran one controlled experiment: the majority-family baseline, an RBF-kernel SVC on 16 numeric columns, and the same model with five categorical columns one-hot encoded into 20 more. The encoding was worth more than every numeric column combined.

  • Part B localized that gain — which families it rescued, and which single column carried it. The answer was a column describing the measurement protocol, not the material.

  • Part C tuned the kernel, found it barely moved the result, and then measured what the split by paper had been protecting against all along.
